**Date**: 2026-09-16

**Target Platform**: Ubuntu 22.04 LTS / ROS2 Humble Hawksbill / Python 3.10

## 1. Executive Summary & Architectural Motivation

With the completion of **Phase A4**, `GenericRobotController` has been fully decoupled from PyBullet:
- Model metadata is governed by `ResolvedRobotModel` (canonical roles, limits, velocities, forces).
- Execution transport is abstracted by `RobotBackend`.
- Kinematics calculations are abstracted by `KinematicsProvider`.
- Spatial collision queries are abstracted by `CollisionProvider`.

**Phase B1** establishes the first real-world transport layer: **Read-Only ROS2 Joint State Telemetry Consumption**.

```
+-------------------------------------------------------------------------+
|                              ROS 2 Graph                                |
|  [robot_state_publisher / joint_state_broadcaster / hardware driver]    |
|                                    |                                    |
|                      sensor_msgs/msg/JointState                         |
|                       Topic: e.g. /joint_states                         |
+------------------------------------+------------------------------------+
                                     |
                                     v
+-------------------------------------------------------------------------+
|                  VisionRobotTwin Execution Layer                        |
|                                                                         |
|  +-------------------------------------------------------------------+  |
|  |                    ROS2JointStateBackend                          |  |
|  |  - Fresh rclpy.Context & SingleThreadedExecutor on each connect   |  |
|  |  - Name-based joint re-ordering & extra-joint pruning             |  |
|  |  - Pure read-only safety guard (Commands fail closed)             |  |
|  |  - Clock domain isolation (source timestamp vs receive timestamp)  |  |
|  |  - Fail-closed stale state protection (BackendStateStaleError)    |  |
|  +---------------------------------+---------------------------------+  |
|                                    |                                    |
|                                    v                                    |
|                        TimestampedJointState                            |
|                        (Positions mandatory; Velocity/Effort optional)  |
|                                    |                                    |
|             +----------------------+----------------------+             |
|             |                                             |             |
|             v                                             v             |
|  GenericRobotController (Read-Only)          Diagnostic Probe Tool      |
|  - get_current_joint_positions()             (tools/ros2_probe.py)      |
|  - get_current_joint_velocities()            - Rate & Latency stats     |
|    (raises FieldUnavailable if None)         - Health status            |
|  - get_end_effector_pose() (via FK)          - Read-only diagnostics    |
+-------------------------------------------------------------------------+
```

### Key Architectural Invariants
1. **Strictly Read-Only**: Absolutely NO command publishing, action client, or controller manager interaction in Phase B1.
2. **Deterministic Joint Mapping**: Messages are matched by string joint name against `expected_joint_names` (from `ResolvedRobotModel.arm_joint_names`), never by raw array indices.
3. **Optional Velocity Semantics**: In `sensor_msgs/msg/JointState`, positions are required, but velocity and effort arrays may be empty. Unknown velocity is NOT zero velocity; empty velocities are preserved as `None`.
4. **Clock Domain Separation**: Source timestamps (ROS header) are isolated from local receipt timestamps (`time.monotonic()`). Freshness is strictly evaluated using `receive_timestamp_s`.
5. **Fail-Closed Stale State**: If telemetry age exceeds `state_timeout_s` (default 1.0s), `health_status()` transitions to `DEGRADED` and `get_joint_state()` raises `BackendStateStaleError`.
6. **Fresh Context Lifecycle**: Each `connect()` allocates a fresh `rclpy.context.Context` and `SingleThreadedExecutor`, never reusing a shut-down context.
7. **Zero Impact on Windows / PyBullet**: All ROS2 modules are strictly optional. Standalone Windows environments without `rclpy` continue running all 214 baseline tests with zero regressions.

## 2. Process & Lifecycle Architecture

### 2.1 Lifecycle & Threading Contract
`ROS2JointStateBackend` implements standard `connect()` / `disconnect()` lifecycle using private ROS context:
- **`connect()`**:
  1. Idempotent check: if already cleanly connected, returns `True`.
  2. Creates a brand new `rclpy.context.Context()`.
  3. Initializes context: `rclpy.init(context=context, domain_id=config.domain_id)`.
  4. Creates node `node_name` inside `node_namespace` with the private context.
  5. Creates subscription to `joint_state_topic` using configured QoS profile (`SensorDataQoS`: KEEP_LAST, depth 5, BEST_EFFORT, VOLATILE, or RELIABLE override).
  6. Creates `SingleThreadedExecutor(context=context)`, adds the node, and spawns a background thread.
  7. Returns `True` immediately without blocking or waiting for the first message.
- **`disconnect()`**:
  1. Idempotent check: if not connected, returns immediately.
  2. Signals executor shutdown from caller thread.
  3. Joins background spin thread with bounded timeout (e.g. 2.0s).
  4. Destroys subscription and node.
  5. Shuts down **only** the backend-owned private `rclpy.Context`.
  6. Resets ROS object references to `None`.
  7. Sets internal health status to `DISCONNECTED`.
- **Private vs Global Context Invariant**:
  `ROS2JointStateBackend` must NEVER call global `rclpy.shutdown()`. It operates strictly on `self._context.shutdown()`, preventing interference with any external ROS nodes operating within the same process.

## 3. Telemetry Ingestion & Mapping Contract

### 3.1 Message Source Contract
- **Message Type**: `sensor_msgs/msg/JointState`
- **Topic**: Configurable (Default `/joint_states`)
- **Field Requirements**:
  - `name`: `string[]` (Mandatory, non-empty, unique)
  - `position`: `float64[]` (Mandatory, `len(position) == len(name)`)
  - `velocity`: `float64[]` (Optional; if empty -> `None`; if non-empty -> `len(velocity) == len(name)`)
  - `effort`: `float64[]` (Optional; if empty -> `None`; if non-empty -> `len(effort) == len(name)`)
  - `header.stamp`: `builtin_interfaces/msg/Time` (sec, nanosec; `0, 0` treated as valid unspecified source stamp)

### 3.2 Canonical Joint Name Mapping & Ordering
ROS2 drivers frequently publish joint states in arbitrary order or include extraneous joints (gripper fingers, chassis joints, virtual joints).

1. **Mapping Invariant**:
   Given configured `expected_joint_names = (name_1, name_2, ..., name_N)`:
   - Construct name index map: `lookup = {name: idx for idx, name in enumerate(msg.name)}`.
   - Verify every required name exists: `all(req_name in lookup for req_name in expected_joint_names)`.
   - Extract in exact configured order:
     - `positions = tuple(msg.position[lookup[name]] for name in expected_joint_names)`
     - `velocities = tuple(msg.velocity[lookup[name]] for name in expected_joint_names)` if `len(msg.velocity) > 0` else `None`
     - `efforts = tuple(msg.effort[lookup[name]] for name in expected_joint_names)` if `len(msg.effort) > 0` else `None`
2. **Pruning Extraneous Joints**:
   Any joint present in `msg.name` that is not in `expected_joint_names` is safely ignored.
3. **Deterministic Rejection Rules (Malformed Telemetry)**:
   A message is marked invalid and dropped if:
   - `msg.name` is empty.
   - `msg.name` contains duplicate entries (ambiguous mapping).
   - Any joint in `expected_joint_names` is missing.
   - `len(msg.position) != len(msg.name)`.
   - `len(msg.velocity) != 0 and len(msg.velocity) != len(msg.name)`.
   - `len(msg.effort) != 0 and len(msg.effort) != len(msg.name)`.
   - Any mapped position, velocity, or effort contains `NaN` or `+/-Inf`.
4. **Resilient Failure Handling**:
   Malformed messages increment `invalid_messages_count` in telemetry diagnostics, record the last error, and do **NOT** raise an unhandled exception or replace the last valid cached state.

## 4. Clock Domains, Freshness, & Health Semantics

### 4.1 Clock Domain Separation
```
+-----------------------------------+-----------------------------------+
|       Source Clock Domain         |        Local Clock Domain         |
| (ROS Header / Middleware / Sim)   |       (time.monotonic())          |
+-----------------------------------+-----------------------------------+
|  msg.header.stamp (sec, nanosec)  |  receive_timestamp_s             |
|  Preserved for trace diagnostics  |  Used for freshness & timeouts    |
+-----------------------------------+-----------------------------------+
```
- **Rule**: Never evaluate staleness by subtracting `time.monotonic()` from `source_timestamp_s`.
- `receive_timestamp_s` is captured via `time.monotonic()` at the moment the callback acquires the message.
- `age_s(current_time_s)` is calculated as `max(0.0, current_time_s - self.receive_timestamp_s)`.

### 4.2 State Availability & Health State Transitions
1. **`DISCONNECTED`**: Prior to `connect()` or after `disconnect()`.
2. **`DEGRADED`**:
   - Connected, but zero valid messages received yet.
   - Connected, but time since last valid message exceeds `state_timeout_s` (default `1.0s`).
3. **`HEALTHY`**: Connected, and `age_s <= state_timeout_s`.
4. **`ERROR`**: Fatal background executor failure.

### 4.3 `get_joint_state()` Semantics
- **Before First Message**: Raises `BackendStateUnavailableError` ("No joint state received yet on topic /joint_states").
- **Stale State (`age > timeout`)**: Raises `BackendStateStaleError` ("Joint state telemetry is stale (age X.XXXs > timeout 1.000s)").
- **Fresh State**: Returns immutable `TimestampedJointState`.

## 5. Read-Only Safety & Command Fail-Closed Policy

`ROS2JointStateBackend` implements `RobotBackend`. All command methods **MUST FAIL CLOSED**:

- **`command_joint_positions(target_positions)`**: Raises `ReadOnlyBackendError("ROS2JointStateBackend is read-only and cannot command robot motion.")`
- **`command_joint_velocities(target_velocities, effort_limit)`**: Raises `ReadOnlyBackendError("ROS2JointStateBackend is read-only and cannot command robot motion.")`
- **`halt_motion()`**: Raises `ReadOnlyBackendError("ROS2JointStateBackend is read-only; halt_motion() cannot halt physical hardware.")`
  - *Invariant*: `halt_motion()` must NOT silently succeed or log "robot stopped" when no command was transmitted.

    """Configuration for ROS2 read-only joint state subscriber backend."""

## 7. Optional Dependency Isolation & Multi-Platform Strategy

### 7.1 Import Isolation
- `robotics/backends/ros2_joint_state_backend.py` encapsulates all `rclpy` and `sensor_msgs` imports.
- `robotics/backends/__init__.py` does NOT unconditionally import `ROS2JointStateBackend` if it requires `rclpy`.
- If instantiated in an environment where `rclpy` is absent, `ROS2JointStateBackend.__init__` raises `OptionalDependencyError`.

### 7.2 Separation of Pure Parser & ROS Middleware
- `robotics/backends/ros2_state_mapping.py` defines pure parsing and validation functions (`map_joint_state_payload`) with zero ROS dependencies. Full test coverage runs natively on Windows.
