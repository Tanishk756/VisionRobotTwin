## 1. Executive Summary & Objective

In **VisionRobotTwin v1.2**, robotics execution, kinematics computations, collision detection, and physics simulation were unified directly around the PyBullet API.

The objective of **VisionRobotTwin v1.3** is to transition the platform into a **backend-agnostic robotics execution framework** while preserving:
1. **Mathematical integrity and performance**: 100% numerical consistency with v1.2 kinematic algorithms.
2. **Deterministic simulation**: Zero-configuration, high-speed 240 Hz PyBullet physics twin as the default on both Windows and Linux.
3. **Future ROS 2 interoperability**: Clean, lazy-loaded ROS 2 transport capability without imposing runtime dependencies on non-ROS environments.

---

## 2. Core Separation of Responsibilities

VisionRobotTwin v1.3 explicitly decouples the robotics stack into three independent domains:

```
+───────────────────────────────────────────────────────────────────────────────────────────────────+
|                                    1. EXECUTION / TRANSPORT LAYER                                 |
|                                         (RobotBackend)                                            |
| Owns ONLY: Connection lifecycle, timestamped joint state acquisition, position/velocity command    |
| dispatch, motion halt, and transport health monitoring.                                           |
+───────────────────────────────────────────────────────────────────────────────────────────────────+
                                                  │
                                                  ▼
+───────────────────────────────────────────────────────────────────────────────────────────────────+
|                                  2. KINEMATICS & MODEL COMPUTATION                                |
|                                       (KinematicsProvider)                                        |
| Owns: Forward kinematics (FK), geometric spatial Jacobian, manipulability metrics, and numerical/ |
| analytical Inverse Kinematics (IK). Does NOT touch hardware drivers or command buses.            |
+───────────────────────────────────────────────────────────────────────────────────────────────────+
                                                  │
                                                  ▼
+───────────────────────────────────────────────────────────────────────────────────────────────────+
|                                     3. WORLD & COLLISION MODEL                                    |
|                                        (CollisionProvider)                                        |
| Owns: Geometric collision checking, obstacle environment representation, self-collision distance  |
| queries, and state-preserving planning validation.                                                |
+───────────────────────────────────────────────────────────────────────────────────────────────────+
```

## 4. Contract Specifications

### 4.1 `TimestampedJointState`

`TimestampedJointState` is an immutable, copy-safe data container. Staleness is computed dynamically relative to a query timestamp.

```python
from dataclasses import dataclass
from typing import List, Optional, Tuple
import numpy as np

@dataclass(frozen=True)
class TimestampedJointState:
    """Immutable, timestamped joint telemetry snapshot from an execution backend."""
    source_timestamp_s: float
    receive_timestamp_s: float
    joint_names: Tuple[str, ...]
    positions: Tuple[float, ...]
    velocities: Tuple[float, ...]
    efforts: Optional[Tuple[float, ...]] = None
    sequence_id: int = 0

    def get_positions_array(self) -> np.ndarray:
        """Returns a copy of joint positions as a NumPy array."""
        return np.array(self.positions, dtype=np.float64)

    def get_velocities_array(self) -> np.ndarray:
        """Returns a copy of joint velocities as a NumPy array."""
        return np.array(self.velocities, dtype=np.float64)

    def age_s(self, current_time_s: float) -> float:
        """Returns the data age in seconds relative to current_time_s."""
        return max(0.0, current_time_s - self.receive_timestamp_s)

    def is_fresh(self, current_time_s: float, timeout_s: float) -> bool:
        """Evaluates whether the telemetry is fresh within the configured timeout window."""
        return self.age_s(current_time_s) <= timeout_s
```

### 4.2 `RobotBackend` (Execution & Transport Boundary)

`RobotBackend` owns strictly I/O and transport lifecycle.

```python
from abc import ABC, abstractmethod
from typing import Sequence
from enum import Enum, auto

class BackendHealthStatus(Enum):
    HEALTHY = auto()
    DEGRADED = auto()
    DISCONNECTED = auto()
    ERROR = auto()

class RobotBackend(ABC):
    """Abstract execution backend interface for robot state acquisition and command transport."""

    @abstractmethod
    def connect(self) -> bool:
        """Establishes transport connection or attaches to existing simulator client."""
        pass

    @abstractmethod
    def disconnect(self) -> None:
        """Closes transport connection / detaches backend and halts joint motion (does not destroy shared simulator world)."""
        pass

    @abstractmethod
    def is_connected(self) -> bool:
        """Returns True if the backend transport is logically attached and underlying connection is active."""
        pass

    @abstractmethod
    def get_joint_state(self) -> TimestampedJointState:
        """Returns the most recent timestamped joint state."""
        pass

    @abstractmethod
    def command_joint_positions(self, target_positions: Sequence[float]) -> bool:
        """Dispatches target joint positions (rad) to the joint controller."""
        pass

    @abstractmethod
    def command_joint_velocities(
        self,
        target_velocities: Sequence[float],
        effort_limit: Optional[float] = None,
    ) -> bool:
        """Dispatches target joint velocities (rad/s) with optional effort/force limit (N/Nm)."""
        pass

    @abstractmethod
    def halt_motion(self) -> None:
        """Sends an immediate software motion stop command (e.g. zero velocities)."""
        pass

    @abstractmethod
    def health_status(self) -> BackendHealthStatus:
        """Returns the transport health and communication state."""
        pass
```

### 4.3 `KinematicsProvider` (Conceptual Model Boundary)

`KinematicsProvider` evaluates forward kinematics, spatial Jacobians, and inverse kinematics for any arbitrary candidate configuration $\mathbf{q}$.

```python
from abc import ABC, abstractmethod
from typing import Optional, Sequence, Tuple
import numpy as np

class KinematicsProvider(ABC):
    """Abstract provider for forward kinematics, Jacobians, and inverse kinematics."""

    @abstractmethod
    def compute_fk(self, joint_positions: Sequence[float]) -> Tuple[np.ndarray, np.ndarray]:
        """Calculates end-effector (position [x,y,z], quaternion [x,y,z,w]) for candidate q."""
        pass

    @abstractmethod
    def compute_jacobian(
        self, joint_positions: Sequence[float]
    ) -> Tuple[np.ndarray, np.ndarray, np.ndarray]:
        """Calculates (J_linear, J_angular, J_full) of shape (3,n), (3,n), (6,n) for candidate q."""
        pass

    @abstractmethod
    def solve_ik(
        self,
        target_position: Sequence[float],
        target_orientation: Optional[Sequence[float]] = None,
        current_joint_positions: Optional[Sequence[float]] = None,
    ) -> "IKResult":
        """Calculates joint configuration matching target Cartesian pose."""
        pass
```

### 4.4 `CollisionProvider` (Conceptual Spatial Boundary)

`CollisionProvider` isolates collision queries from both kinematics and transport.

```python
from abc import ABC, abstractmethod
from typing import Sequence

class CollisionProvider(ABC):
    """Abstract provider for self-collision and environment proximity checks."""

    @abstractmethod
    def check_configuration_collision(
        self, joint_positions: Sequence[float]
    ) -> "CollisionResult":
        """Performs state-preserving collision queries for candidate q against self and world."""
        pass
```

## 5. Command Authority, Controller Boundary & Transport Semantics

- **Single Command Authority**: `GenericRobotController` is the **only entity** permitted to command `RobotBackend`.
- **Policy Enforcement**:
  - `GenericRobotController` owns coordinated position slew rate limiting ($\Delta q_i = \text{clip}(q_{\text{target}, i} - q_{\text{current}, i}, -v_{\max, i} \Delta t, v_{\max, i} \Delta t)$).
  - `GenericRobotController` owns per-joint velocity clamping.
  - `GenericRobotController` owns NaN/Inf command rejection.
- **Effort & Force Semantics (Ruling A)**:
  - `GenericRobotController.set_arm_joint_velocities(target_joint_velocities, max_force: Optional[float] = None)` preserves its public signature and forwards `max_force -> effort_limit` to `RobotBackend.command_joint_velocities(target_velocities, effort_limit)`.
  - For `PyBulletRobotBackend`, if `effort_limit is None`, the robot's configured default joint force (`spec.max_joint_force`) is applied; if `effort_limit` is explicitly provided, `float(effort_limit)` is passed to `p.setJointMotorControlArray(... forces=...)`.
  - Velocity clamping remains strictly in `GenericRobotController`; the backend solely handles requested effort/force limit dispatch.
- **PyBullet Client Ownership & Lifecycle (Ruling B)**:
  - `PyBulletSimulator` owns `p.connect()`, `p.disconnect()`, physics stepping, and world lifecycle.
  - `PyBulletRobotBackend` receives an already existing `physics_client_id` and `robot_body_id`.
  - `connect()`: Validates that the supplied `physics_client_id` is live and marks the backend logically attached/active.
  - `disconnect()`: Halts motion and marks the backend logically detached; **never calls `p.disconnect()`** on the shared simulator physics client.
  - `is_connected()`: Requires both logical attachment and active PyBullet connection (`p.getConnectionInfo(client_id)["isConnected"]`).
- **Backend Role**: `RobotBackend` performs transport I/O only and does **not** duplicate high-level motion policies or trajectory synthesis.
- **Mock Backend**: `MockRobotBackend` is strictly internal test infrastructure and is never exposed in the production CLI.
- **Home vs Teleport**:
  - `GenericRobotController.reset_to_home()` may remain PyBullet-specific during Phase A1 as part of simulation initialization and backward compatibility. It is strictly not a generic physical-hardware homing routine; physical homing remains a high-level `MotionManager` concern.
  - Simulation teleport (`p.resetJointState`) is strictly quarantined inside simulation setup and testing tools.

## 6. Software Safety Model

> [!IMPORTANT]
> **Safety Notice**: VisionRobotTwin software safety checks, rate limiters, and watchdogs are application-level software controls. They are **NOT safety-rated** under ISO 13849-1 / IEC 62061 and do not replace certified robot controller safety zones, hardware interlocks, or physical manufacturer Emergency Stop (E-Stop) buttons.

- Keyboard `[SPACE]` is designated as: **`Application HOLD / Software Motion Stop`** (commands zero joint velocities and holds current setpoint).
- Software watchdog monitoring operates as a **best-effort software guard** to halt commanded motion upon telemetry loss.

## 7. Transitional Technical Debt in Phase A1

In Phase A1, `GenericRobotController` continues to inspect URDF joint metadata (`p.getNumJoints`, `p.getJointInfo`, `p.getLinkState` during initialization) and execute simulation reset (`reset_to_home`) from the loaded PyBullet body ID.

This is documented as **Transitional Technical Debt**. Phase A1 decouples **Runtime Execution I/O** (`getJointStates`, `setJointMotorControlArray`) into `PyBulletRobotBackend`. Complete decoupling of URDF parsing and kinematics queries is deferred to Phase A2 (`KinematicsProvider`).
