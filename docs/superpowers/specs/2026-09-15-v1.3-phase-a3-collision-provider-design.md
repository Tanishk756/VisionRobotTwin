# Phase A3 Specification — CollisionProvider Boundary

## 1. Executive Summary & Objective
VisionRobotTwin v1.3 transforms the architecture from a monolithic PyBullet-bound system into a modular, backend-agnostic digital twin.
- **Phase A1 (Completed)** established the execution backend boundary (`RobotBackend`).
- **Phase A2 (Completed)** established the analytical model boundary (`KinematicsProvider`).
- **Phase A3 (Current)** establishes the world geometry and collision query boundary (`CollisionProvider`).

In Phase A3, spatial collision detection, self-collision evaluation, obstacle proximity checks, and joint-space path feasibility querying are inverted through an abstract interface: `CollisionProvider`. 
Planning algorithms (`RRTConnectPlanner`, `is_joint_path_collision_free`, `shortcut_path`) and orchestration layers (`MotionManager`, `PyBulletSimulator`) will depend purely on `CollisionProvider` rather than concrete PyBullet engine details or PyBullet body/link identifiers.

```

|         (main.py / VisionRobotTwinApp / Autonomous Pick-and-Place)          |
```

## 2. Current PyBullet Coupling Audit (collision.py & planning.py)

### Direct PyBullet API Calls in `robotics/collision.py`
1. `p.getNumJoints`: Discovers total joints in the multi-body tree.
2. `p.getJointInfo`: Inspects joint type (`p.JOINT_FIXED`), link index, and parent link index.
3. `p.getJointState`: Reads `(q, dq)` to save active robot state prior to candidate evaluation.
4. `p.resetJointState`: Writes candidate `q` (with `targetVelocity=0.0`) and restores initial `(q, dq)`.
5. `p.performCollisionDetection`: Triggers internal PyBullet collision pipeline update without advancing time.
6. `p.getContactPoints`: Queries discrete contact penetrations (`distance <= 0.0`).
7. `p.getClosestPoints`: Queries Euclidean proximity between bodies/links within specified thresholds.

### Coupling in `robotics/planning.py`
1. Hard dependency on concrete `CollisionChecker`.
2. Functions require `arm_joint_indices: Optional[List[int]]` alongside configurations to map candidate vectors to PyBullet joint IDs.
3. Planning search algorithms cannot run without an active PyBullet simulation server and connected physics client ID.

### Classification of Collision Concepts
| Concept | Classification | Treatment in Phase A3 |
| :--- | :--- | :--- |
| `check_collision(q)` | **A. Generic query concept** | Canonical method on `CollisionProvider`. |
| `in_collision`, `min_distance_m` | **A. Generic query concept** | Preserved in `CollisionResult`. |
| `p.performCollisionDetection` | **B. PyBullet engine detail** | Encapsulated in `PyBulletCollisionProvider`. |
| `p.getContactPoints` / `getClosestPoints` | **B. PyBullet engine detail** | Encapsulated in `PyBulletCollisionProvider`. |
| Adjacent-link tree traversal & fixed closures | **C. Robot topology metadata** | Initialized inside `PyBulletCollisionProvider`. |
| `colliding_bodies`, `colliding_links` (int IDs)| **D. Provider diagnostic metadata**| Retained as diagnostic fields in `CollisionResult`. |

## 3. Shared Model Mutation Synchronization (Critical Architectural Fix)

### The Race Condition Problem
In Phase A2, `PyBulletKinematicsProvider.compute_fk(q)` was implemented with an `RLock` to serialize candidate joint overrides (`p.resetJointState`).
`CollisionChecker.check_collision(q)` similarly overrides `p.resetJointState` to evaluate collisions at candidate configurations.
If `PyBulletKinematicsProvider` and `PyBulletCollisionProvider` instantiate independent locks, concurrent queries against the same PyBullet robot body can corrupt temporary joint state registers.

### The Solution: Shared Model-Query Lock
1. A single `threading.RLock()` context is established per robot body / simulation instance.
2. `PyBulletSimulator` instantiates `self._model_query_lock = threading.RLock()`.
3. The shared lock is injected into both:
   - `PyBulletKinematicsProvider(..., query_lock=self._model_query_lock)`
   - `PyBulletCollisionProvider(..., query_lock=self._model_query_lock)`
4. If no external `query_lock` is provided in standalone constructors, each provider defaults to instantiating its own private `threading.RLock()`, ensuring full backward compatibility.
5. `PyBulletKinematicsProvider` and `PyBulletCollisionProvider` expose a read-only property `query_lock` for validation and introspection.

```python
# Shared Lock Concept
class PyBulletCollisionProvider(CollisionProvider):
    def __init__(self, ..., query_lock: Optional[threading.RLock] = None):
        self._lock = query_lock if query_lock is not None else threading.RLock()
```

> [!IMPORTANT]
> **Threading Scope Precision**: The shared `RLock` serializes candidate PyBullet joint register mutations (`resetJointState`) between kinematics and collision queries. It does **not** make PyBullet globally thread-safe, does not provide hard real-time synchronization, and does not synchronize asynchronous physics stepping with rendering.

## 4. Abstract Contract: `CollisionProvider`

The `CollisionProvider` abstract base class defines the minimal boundary necessary for joint-space planning and state monitoring:

```python
from abc import ABC, abstractmethod
from typing import Optional, Sequence
from robotics.collision import CollisionResult

class CollisionProvider(ABC):
    """Abstract interface for robot collision detection and proximity queries."""

    @abstractmethod
    def check_collision(
        self,
        joint_positions: Optional[Sequence[float]] = None,
    ) -> CollisionResult:
        """Evaluates collision status for the current or candidate joint configuration.

        Args:
            joint_positions: Optional candidate joint configuration vector for controllable
                arm joints. If None, queries collision state at current robot configuration.

        Returns:
            CollisionResult containing collision flags, minimum clearances, and diagnostics.
        """
        pass
```

### YAGNI Guard
Generic methods such as `add_obstacle()`, `remove_obstacle()`, `attach_mesh()`, or `get_planning_scene()` are **not** added to the abstract `CollisionProvider` contract because existing planners only require state evaluation (`check_collision`). Concrete world manipulation methods remain on `PyBulletCollisionProvider` or `PyBulletSimulator`.

## 5. `CollisionResult` Data Structure Strategy

`CollisionResult` remains structurally unchanged in Phase A3 to maintain 100% backward compatibility with all benchmark suites, integration tests, and telemetry reporters:

```python
@dataclass
class CollisionResult:
    """Represents the collision evaluation outcome."""
    in_collision: bool
    self_collision: bool = False
    env_collision: bool = False
    min_distance_m: float = float("inf")
    min_env_clearance_m: float = float("inf")
    min_self_clearance_m: float = float("inf")
    colliding_bodies: List[Tuple[int, int]] = field(default_factory=list)
    colliding_links: List[Tuple[int, int]] = field(default_factory=list)
    details: str = ""
```

### Clearance & Penetration Semantics
- `min_env_clearance_m`: Minimum Euclidean distance between robot links and environment objects (query search distance: 1.0 m; returns `inf` if no obstacles within 1.0 m).
- `min_self_clearance_m`: Minimum Euclidean distance between non-adjacent/non-whitelisted robot links (query search distance: 0.5 m; returns `inf` if no links within 0.5 m).
- `min_distance_m`: `min(min_env_clearance_m, min_self_clearance_m)`.
- Penetration / active contact is defined as distance $\le 0.0$ m.
- `colliding_bodies` and `colliding_links` contain integer IDs under `PyBulletCollisionProvider` and are documented as transitional engine diagnostics.

## 6. Concrete Implementation: `PyBulletCollisionProvider`

`PyBulletCollisionProvider` encapsulates all PyBullet C-API collision calls and topology inspections:
- **Constructor Parameters**:
  - `physics_client_id: int`
  - `robot_body_id: int`
  - `arm_joint_indices: Sequence[int]`
  - `table_id: Optional[int] = None`
  - `obstacle_ids: Optional[Sequence[int]] = None`
  - `allowed_body_pairs: Optional[Sequence[Tuple[int, int]]] = None`
  - `allowed_link_pairs: Optional[Sequence[Tuple[int, int, int, int]]] = None`
  - `allowed_self_link_pairs: Optional[Sequence[Tuple[int, int]]] = None`
  - `query_lock: Optional[threading.RLock] = None`
- **State Preservation Guarantees**:
  - Validates candidate `joint_positions` length against `len(arm_joint_indices)`.
  - Rejects `NaN` and `Inf` with `ValueError`.
  - Captures initial `(idx, q, dq)` for all arm joints.
  - Applies candidate `q` via `p.resetJointState(..., targetVelocity=0.0)`.
  - Calls `p.performCollisionDetection()`.
  - In a `finally` block: unconditionally restores initial `(q, dq)` and calls `p.performCollisionDetection()`.
  - Never invokes `p.stepSimulation()`.

## 7. Backward Compatibility: `CollisionChecker` Alias/Subclass

To avoid breaking external scripts, benchmarks, or existing unit tests:
1. `CollisionChecker` in `robotics/collision.py` becomes a subclass of `PyBulletCollisionProvider`.
2. `CollisionChecker` inherits all methods and signatures from `PyBulletCollisionProvider`.
3. If `arm_joint_indices` is passed to `check_collision(joint_positions, arm_joint_indices)`, it is accepted for backward compatibility.
4. If `arm_joint_indices` was omitted during `__init__`, `CollisionChecker` discovers active non-fixed joints automatically.

## 8. Planning and Motion Manager Inversion

### `robotics/planning.py`
- Imports `CollisionProvider` (not `CollisionChecker`).
- Functions and classes updated:
  - `is_joint_path_collision_free(q_start, q_goal, collision_provider: CollisionProvider, resolution_rad: float = 0.05, arm_joint_indices: Optional[List[int]] = None)`
  - `RRTConnectPlanner(lower_limits, upper_limits, collision_provider: CollisionProvider, arm_joint_indices: Optional[List[int]] = None, ...)`
  - `shortcut_path(path, collision_provider: CollisionProvider, arm_joint_indices: Optional[List[int]] = None, ...)`
- `arm_joint_indices` is retained as an optional compatibility argument, but internal collision queries delegate directly to `collision_provider.check_collision(wpt)`.
- Algorithms (bidirectional RRT-Connect, shortcutting, straight-line interpolation) remain mathematically identical.

### `robotics/motion_manager.py`
- `MotionManager.__init__` accepts `collision_provider: Optional[CollisionProvider] = None` (with `collision_checker` supported as positional or aliased keyword).
- Motion planning lifecycle (`plan_motion_to_pose`) delegates path checking and RRT planning using `self.collision_provider`.

## 9. Simulator Integration Architecture

`PyBulletSimulator` in `robotics/simulator.py` wires the single canonical provider context:
```python
# 1. Instantiate shared model-query lock
self._model_query_lock = threading.RLock()

# 2. Controller & Kinematics Provider with shared lock
self.controller = GenericRobotController(..., query_lock=self._model_query_lock)
self.kinematics_provider = self.controller.kinematics_provider

# 3. Collision Provider with shared lock
self.collision_provider = PyBulletCollisionProvider(
    physics_client_id=self.client_id,
    robot_body_id=self.robot_id,
    arm_joint_indices=self.controller.arm_joint_indices,
    table_id=self.table_id,
    obstacle_ids=self.obstacle_ids,
    allowed_link_pairs=allowed_mount_pairs,
    allowed_self_link_pairs=self.robot_spec.allowed_self_collision_pairs,
    query_lock=self._model_query_lock,
)
self.collision_checker = self.collision_provider  # Backward-compatibility alias

# 4. MotionManager wired with shared collision_provider
self.motion_manager = MotionManager(
    robot_controller=self.controller,
    ik_solver=self.ik_solver,
    collision_checker=self.collision_provider,
    ...
)
```

## 10. Future MoveIt2 Compatibility (Design Note)
A future `MoveIt2CollisionProvider` or `PlanningSceneCollisionProvider` will implement `CollisionProvider`:
- `check_collision(joint_positions)` will query the ROS 2 `/check_state_validity` service or local PlanningScene monitor.
- Returns standard `CollisionResult`.
- `RRTConnectPlanner` and `MotionManager` will execute without knowing whether the backend is PyBullet or MoveIt2.
