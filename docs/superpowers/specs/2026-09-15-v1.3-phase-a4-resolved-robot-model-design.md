# Specification: Phase A4 — Resolved Robot Model and Controller Model-Metadata Boundary

## 1. Executive Summary & Problem Statement
Following the completion of **Phase A1** (`RobotBackend`), **Phase A2** (`KinematicsProvider`), and **Phase A3** (`CollisionProvider`), all major robotics execution, kinematics, and collision query services have been decoupled from direct PyBullet engine bindings.

However, **`GenericRobotController`** remains tightly coupled to PyBullet at initialization time:
1. It imports `pybullet as p` and directly invokes C-API queries (`p.getNumJoints`, `p.getJointInfo`, `p.JOINT_REVOLUTE`, `p.JOINT_PRISMATIC`, `p.resetJointState`).
2. Its constructor requires mandatory `physics_client_id` and `robot_id` integers.
3. It performs runtime URDF inspection via `_inspect_urdf()` by querying the active PyBullet physics server directly.
4. It executes an implicit simulation teleport (`reset_to_home()` using `p.resetJointState`) as a constructor side effect.

Consequently, injecting a `MockRobotBackend` or future `ROS2RobotBackend` into `GenericRobotController` cannot succeed without spinning up a live PyBullet simulation client and loading a URDF into it.

**Phase A4** resolves this final foundation barrier by establishing a clear separation between:
- **`RobotModelSpec`**: Declarative static configuration, hardware capability flags, and path patterns.
- **`ResolvedRobotModel`**: Strongly-typed, immutable runtime model metadata (ordered arm joints, gripper joints, limits, velocities, forces, link names, end-effector identification, home poses).
- **`PyBulletRobotModelResolver`**: PyBullet-specific URDF inspection and adapter limit-fixing utility that produces a `ResolvedRobotModel`.
- **`GenericRobotController`**: Pure control policy, rate limiting, velocity clamping, and metadata consumer operating via `ResolvedRobotModel`, `RobotBackend`, and `KinematicsProvider` with **0 PyBullet imports and 0 direct PyBullet calls** in the generic path.

## 2. Comparison of Architectural Approaches

### Approach A: Monolithic Spec Expansion
- **Description**: Expand `RobotModelSpec` to hardcode all joint names, joint limits, velocities, forces, and link names directly in Python dictionaries.
- **Pros**: Trivial runtime construction.
- **Cons**: Duplicates URDF truth in static source code; high maintenance; model-specific hardcoding; breaks when URDFs are modified or swapped; unviable for arbitrary URDFs.
- **Verdict**: **Rejected**.

### Approach B: Resolved Robot Model Data Product with Engine-Specific Resolver (**Selected**)
- **Description**: Introduce immutable `ResolvedJointMetadata` and `ResolvedRobotModel` data structures. Implement `PyBulletRobotModelResolver` to inspect PyBullet URDFs, apply adapter fixes, and emit `ResolvedRobotModel`. `GenericRobotController` consumes `ResolvedRobotModel`.
- **Pros**: Clean separation of concerns; controller is 100% backend-agnostic; no duplicate constants; future ROS2 `/robot_description` or URDF parsers can emit the identical `ResolvedRobotModel`; adheres to YAGNI.
- **Cons**: Requires mapping PyBullet URDF inspection into the data model during simulation setup.
- **Verdict**: **Selected**.

### Approach C: Full Model Provider ABC Hierarchy
- **Description**: Introduce `RobotModelProvider(ABC)` with `PyBulletRobotModelProvider` and future ROS2 providers.
- **Pros**: Symmetrical with `KinematicsProvider` and `CollisionProvider`.
- **Cons**: Model resolution is a one-shot ingestion/factory pipeline rather than a continuous query service; introducing an ABC before having a second engine violates YAGNI.
- **Verdict**: **Deferred** until multiple runtime resolution engines exist. Approach B easily wraps into an ABC later if needed.

## 3. Data Model Architecture

### 3.1 `JointRole`
```python
from enum import Enum, auto

class JointRole(Enum):
    """Categorized role of a robot joint in manipulator control."""
    ARM = auto()
    GRIPPER = auto()
    OTHER = auto()
```

### 3.2 `ResolvedJointMetadata`
```python
@dataclass(frozen=True)
class ResolvedJointMetadata:
    """Immutable metadata for an individual robot joint.

    Attributes:
        canonical_index: Contiguous 0-based index within its specific role (e.g. 0..6 for 7-DoF arm).
        name: Joint identifier name (e.g. 'panda_joint1').
        role: Functional role (ARM, GRIPPER, or OTHER).
        lower_limit: Minimum joint position limit (rad or m).
        upper_limit: Maximum joint position limit (rad or m).
        max_force: Maximum allowable effort/torque (N or Nm).
        max_velocity: Maximum allowable angular or linear velocity (rad/s or m/s).
        link_name: Name of the child link attached to this joint.
        native_index: Optional engine-native index (e.g. PyBullet joint integer ID).
    """
    canonical_index: int
    name: str
    role: JointRole
    lower_limit: float
    upper_limit: float
    max_force: float
    max_velocity: float
    link_name: str
    native_index: Optional[int] = None
```

### 3.3 `ResolvedRobotModel`
```python
@dataclass(frozen=True)
class ResolvedRobotModel:
    """Immutable, fully resolved kinematic and dynamic metadata for a robotic manipulator.

    Attributes:
        robot_id: String identifier (e.g. 'panda', 'kuka_iiwa').
        display_name: Human-readable model name.
        all_joints: Tuple of all parsed joints in topological/URDF order.
        arm_joints: Tuple of controllable arm joints in canonical order.
        gripper_joints: Tuple of gripper/finger joints in canonical order.
        ee_link_name: Name of the active end-effector link.
        ee_link_native_index: Optional engine-native link index.
        home_joint_positions: Canonical home joint angles (rad).
        capabilities: Hardware capability flags.
    """
    robot_id: str
    display_name: str
    all_joints: Tuple[ResolvedJointMetadata, ...]
    arm_joints: Tuple[ResolvedJointMetadata, ...]
    gripper_joints: Tuple[ResolvedJointMetadata, ...]
    ee_link_name: str
    ee_link_native_index: Optional[int] = None
    home_joint_positions: Tuple[float, ...] = ()
    capabilities: RobotCapabilities = field(
        default_factory=lambda: RobotCapabilities(has_gripper=False, supports_pick_place=False)
    )

    @property
    def dof(self) -> int:
        """Controllable arm degrees of freedom."""
        return len(self.arm_joints)

    @property
    def arm_joint_names(self) -> Tuple[str, ...]:
        return tuple(j.name for j in self.arm_joints)

    @property
    def arm_lower_limits(self) -> Tuple[float, ...]:
        return tuple(j.lower_limit for j in self.arm_joints)

    @property
    def arm_upper_limits(self) -> Tuple[float, ...]:
        return tuple(j.upper_limit for j in self.arm_joints)

    @property
    def arm_joint_ranges(self) -> Tuple[float, ...]:
        return tuple(j.upper_limit - j.lower_limit for j in self.arm_joints)

    @property
    def arm_max_velocities(self) -> Tuple[float, ...]:
        return tuple(j.max_velocity for j in self.arm_joints)

    @property
    def arm_max_forces(self) -> Tuple[float, ...]:
        return tuple(j.max_force for j in self.arm_joints)

    @property
    def arm_native_indices(self) -> Tuple[int, ...]:
        return tuple(j.native_index for j in self.arm_joints if j.native_index is not None)

    @property
    def gripper_native_indices(self) -> Tuple[int, ...]:
        return tuple(j.native_index for j in self.gripper_joints if j.native_index is not None)
```

## 4. PyBullet Robot Model Resolver

The resolver is housed in `robotics/pybullet_model.py`. It encapsulates all PyBullet C-API model inspection:

```python
class PyBulletRobotModelResolver:
    """Inspects a PyBullet physics client body and produces an immutable ResolvedRobotModel."""

    @staticmethod
    def resolve(
        physics_client_id: int,
        robot_body_id: int,
        spec: RobotModelSpec,
        adapter: Optional[RobotAdapter] = None,
    ) -> ResolvedRobotModel:
        ...
```

### 4.1 Joint Classification & Policy
1. Query `num_joints = p.getNumJoints(robot_body_id, physicsClientId=physics_client_id)`.
2. For each joint `i`:
   - Extract `name`, `joint_type`, `lower`, `upper`, `max_force`, `max_vel`, `link_name`.
   - Apply `adapter.fix_joint_limits(joint_name, lower, upper)`.
   - Apply fallback force `spec.max_joint_force` if URDF specifies `<= 0`.
   - Apply fallback velocity `spec.max_joint_velocity_radps` if URDF specifies `<= 0`.
3. **Role Classification**:
   - Matches `joint_name` against `spec.arm_joint_name_patterns` and `spec.gripper_joint_name_patterns`, while respecting `joint_type == p.JOINT_REVOLUTE` (arm) and `joint_type == p.JOINT_PRISMATIC` (gripper) as secondary confirmation.
   - Preserves exact Panda 7-arm + 2-gripper and KUKA 7-arm + 0-gripper classifications.
4. **End-Effector Identification**:
   - Calls `adapter.identify_ee_link_index(joint_info_map, default_index)`.
   - Resolves `ee_link_name` and `ee_link_native_index`.
5. Emits `ResolvedRobotModel`.

## 5. GenericRobotController Refactoring

### 5.1 Constructor Contract
```python
class GenericRobotController:
    """Robot-agnostic controller for multi-DoF robotic manipulators."""

    def __init__(
        self,
        physics_client_id: Optional[int] = None,
        robot_id: Optional[int] = None,
        spec: Optional[RobotModelSpec] = None,
        adapter: Optional[RobotAdapter] = None,
        config: Optional[RobotConfig] = None,
        backend: Optional[RobotBackend] = None,
        kinematics_provider: Optional[KinematicsProvider] = None,
        model_query_lock: Optional[threading.RLock] = None,
        resolved_model: Optional[ResolvedRobotModel] = None,
    ):
```

### 5.2 Initialization Logic & Decoupling
1. **Model Resolution**:
   - If `resolved_model` is provided: `self.model = resolved_model`, `self.spec = spec or ...`.
   - If `resolved_model` is `None`: Legacy path. If `physics_client_id` and `robot_id` are provided, invokes `PyBulletRobotModelResolver.resolve(...)`.
2. **Kinematics Provider**:
   - If provided: use it directly.
   - If `None` and PyBullet handles exist: constructs `PyBulletKinematicsProvider(client_id, robot_id, arm_joint_indices=self.model.arm_native_indices, ...)`.
   - If `None` and no PyBullet handles: raises `ValueError("kinematics_provider must be supplied when constructing without PyBullet client.")`.
3. **Backend**:
   - If provided: use it directly.
   - If `None` and PyBullet handles exist: constructs `PyBulletRobotBackend(client_id, robot_id, arm_joint_indices=self.model.arm_native_indices, joint_names=self.model.arm_joint_names, ...)`.
   - If `None` and no PyBullet handles: raises `ValueError("backend must be supplied when constructing without PyBullet client.")`.
4. **Backend & Model Validation**:
   - Validates that `backend.get_joint_state()` joint names (or backend count) match `self.model.arm_joint_names`.
5. **Teleport / Home Side Effects**:
   - **NO automatic `reset_to_home()` in generic constructor**.
   - For legacy PyBullet constructor calls where `physics_client_id` was passed, optional legacy compatibility can call simulation teleport if explicitly desired, but standard construction does not move or teleport the robot.

### 5.3 Methods Operating on `ResolvedRobotModel`
- `get_joint_limits()`: Returns `(list(self.model.arm_lower_limits), list(self.model.arm_upper_limits), list(self.model.arm_joint_ranges), list(self.model.home_joint_positions[:self.model.dof]))`.
- `set_arm_joint_positions(target_positions, dt, enforce_velocity_limits)`: Uses `self.model.arm_max_velocities` for slew-rate limiting, delegates to `self.backend.command_joint_positions()`.
- `set_arm_joint_velocities(target_velocities, max_force)`: Clamps against `self.model.arm_max_velocities`, delegates to `self.backend.command_joint_velocities()`.
- `get_current_joint_positions()`, `get_current_joint_velocities()`: Delegate to `self.backend.get_joint_state()`.
- `get_end_effector_pose()`: Delegates to `self.kinematics_provider.compute_fk()`.
- `compute_cartesian_error(target_position)`: Computes norm against `get_end_effector_pose()`.

## 6. Simulation Teleport Separation
Simulation initial state initialization is moved to `PyBulletSimulator`:
```python
# In robotics/pybullet_model.py
def teleport_robot_to_home(
    physics_client_id: int,
    robot_body_id: int,
    resolved_model: ResolvedRobotModel,
) -> None:
    """Sets joint state teleport in PyBullet simulation to the home configuration."""
    for idx, jinfo in enumerate(resolved_model.arm_joints):
        target_angle = resolved_model.home_joint_positions[idx] if idx < len(resolved_model.home_joint_positions) else 0.0
        p.resetJointState(robot_body_id, jinfo.native_index, target_angle, targetVelocity=0.0, physicsClientId=physics_client_id)

    for jinfo in resolved_model.gripper_joints:
        p.resetJointState(robot_body_id, jinfo.native_index, 0.04, targetVelocity=0.0, physicsClientId=physics_client_id)
```
`PyBulletSimulator._setup_robot_and_kinematics()` calls `teleport_robot_to_home(...)` during simulator setup.
Legacy `GenericRobotController.reset_to_home()` calls `teleport_robot_to_home` if `self.client_id` and `self.robot_id` are available, or raises an error if called in a purely decoupled/mock environment.

## 7. Engine Handles & Provider Boundaries

| Service | Consumed Handle | Origin |
|---|---|---|
| `GenericRobotController` | `ResolvedRobotModel` (canonical) | Model Resolver |
| `RobotBackend` (PyBullet) | `arm_native_indices: Tuple[int, ...]` | `ResolvedRobotModel.arm_native_indices` |
| `KinematicsProvider` (PyBullet) | `arm_joint_indices: Tuple[int, ...]`, `ee_link_index: int` | `ResolvedRobotModel.arm_native_indices`, `ResolvedRobotModel.ee_link_native_index` |
| `CollisionProvider` (PyBullet) | `arm_joint_indices: Tuple[int, ...]` | `ResolvedRobotModel.arm_native_indices` |

`GenericRobotController` does NOT pass or store PyBullet C-API types, link structures, or joint indices.

## 8. Preserved APIs & Backward Compatibility
1. **Positional Arguments**: `GenericRobotController(physics_client_id, robot_id, spec, adapter, config, backend, kinematics_provider, model_query_lock, resolved_model)` preserves all positional slots.
2. **`PandaRobotController`**: Retains constructor signature `(physics_client_id, robot_id, config, robot_config, kinematics_provider)`.
3. **`JointInfo`**: Retained in `robotics/robot_controller.py` as backward-compatible alias/dataclass if external tests inspect `controller.joints`.
4. **`controller.arm_joint_indices` & `controller.finger_joint_indices`**: Retained as properties delegating to `self.model.arm_native_indices` and `self.model.gripper_native_indices` for backward compatibility.
5. **No Parameter Renaming on Public APIs**: All existing methods retain identical signatures and return types.

## 9. Scope Exclusions for Phase A4
- **No ROS2 packages or `rclpy` imports**.
- **No `ROS2RobotBackend` implementation** (Deferred to Phase B).
- **No MoveIt2 or TF2 bindings**.
- **No external URDF parsing libraries (e.g. `urdf_parser_py`)**.
