# Implementation Plan: Phase A4 — Resolved Robot Model and Controller Model-Metadata Boundary

## 1. Overview & Goals
Phase A4 completes the core architectural decoupling of `GenericRobotController` from PyBullet. After this phase:
- `GenericRobotController` consumes an immutable `ResolvedRobotModel`, `RobotBackend`, and `KinematicsProvider`.
- `GenericRobotController` can be constructed and operated with `MockRobotBackend` without a live PyBullet simulation, connection, or top-level PyBullet import.
- `robotics/robot_controller.py` contains **0 direct PyBullet C-API calls** in the generic execution path and **0 top-level PyBullet imports**.
- `JointMotionType` preserves kinematic joint types without engine integer constants.
- `ResolvedJointMetadata` contains `model_index` (unique model-wide 0-based index) and `canonical_index` (role-local index).
- Simulation initial state teleport is decoupled from generic controller instantiation.
- Backward-compatible constructor and method signatures are completely preserved.
