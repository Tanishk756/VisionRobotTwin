# Phase B1 Implementation Plan — Read-Only ROS2 Joint State Integration

**Target Version**: 1.3.0-dev  
**Milestone**: Phase B1 — Read-Only ROS2 Joint State Backend  
**Baseline**: 214 tests passing on `develop/v1.3.0`  
**Execution Strategy**: Strict TDD, small reviewable commits, pure Python unit tests on Windows + real ROS2 integration tests on Linux.

---

## Task Decomposition Overview

- **Task 1**: Define backend exceptions (`ReadOnlyBackendError`, `BackendStateUnavailableError`, `OptionalDependencyError`) & evolve `TimestampedJointState` optional velocity support if needed.
- **Task 2**: Implement pure JointState mapping & parsing logic (`robotics/backends/ros2_state_mapping.py`).
- **Task 3**: Implement `ROS2JointStateBackendConfig` and `ROS2BackendDiagnostics` data schemas.
- **Task 4**: Implement `ROS2JointStateBackend` with private `rclpy.Context`, `SingleThreadedExecutor`, and background spin thread.
- **Task 5**: Enforce fail-closed read-only command rejection on all command APIs.
- **Task 6**: Implement thread-safe state cache, freshness detection, and `BackendHealthStatus` transitions.
- **Task 7**: Implement optional dependency handling & standalone import safety (no `rclpy` required).
- **Task 8**: Build standalone read-only telemetry probe tool (`tools/ros2_joint_state_probe.py`).
- **Task 9**: Create Linux ROS2 Humble real integration tests (`tests/ros2/test_ros2_joint_state_backend.py`) and CI workflow.
- **Task 10**: Full verification across Windows (214 baseline + new tests) and Linux ROS2.
