## 1. Goal & Architectural Overview

Phase A1 establishes the **Execution Backend Boundary** for VisionRobotTwin. It introduces the abstract `RobotBackend` interface and `TimestampedJointState` data model, creates an internal `MockRobotBackend` for standalone contract testing, implements `PyBulletRobotBackend` for PyBullet joint I/O, and refactors `GenericRobotController` to delegate runtime joint reads and writes to `RobotBackend`.

```
[MotionManager / ResolvedRateController]
                     │
                     ▼
          [GenericRobotController]  <─── Sole Command Authority Owner
                     │ (Coordinated Slew Limiting & Per-Joint Velocity Clamping)
                     ▼
          [<<abstract>> RobotBackend]
            ├── PyBulletRobotBackend (Default Runtime Execution)
            └── MockRobotBackend     (Internal Test Infrastructure)
```

- **Spec Document**: [docs/superpowers/specs/2026-09-15-v1.3-backend-architecture-design.md](file:///C:/Users/droni/.gemini/antigravity-ide/scratch/VisionRobotTwin/docs/superpowers/specs/2026-09-15-v1.3-backend-architecture-design.md)
- **Tech Stack**: Python 3.10 / 3.11 / 3.12, NumPy 2.x, PyBullet 3.2.7, pytest.
- **Baseline Requirement**: All 131 pre-existing tests remain 100% passing across Windows Python 3.11 and 3.12.

## 2. Global Constraints & Transitional Rules

1. **Test Baseline**: All 131 pre-existing unit and integration tests must remain passing. New tests will increase the total test count.
2. **Mock Backend Scope**: `MockRobotBackend` is **test infrastructure only**. It must **not** be exposed as a `--backend mock` CLI option in production.
3. **Transitional Technical Debt**: In Phase A1, `GenericRobotController` continues to read static URDF joint metadata (`p.getNumJoints`, `p.getJointInfo`, `p.getLinkState` during initialization) from the loaded PyBullet body ID. Only **runtime joint I/O** (`getJointStates`, `setJointMotorControlArray`) is migrated to `PyBulletRobotBackend`. Complete kinematics decoupling is deferred to Phase A2 (`KinematicsProvider`).
4. **Command Authority**: `GenericRobotController` remains the sole command authority. `RobotBackend` performs transport I/O only and does **not** duplicate rate-limiting or velocity-clamping policies.
5. **No ROS 2 Runtime Code**: Zero `rclpy` imports or ROS 2 files in Phase A1.
6. **Reference Artifact Immutability**: All files under `docs/experiments/v1.2_reference/` must remain byte-for-byte unchanged.

### Task 6: Refactor `GenericRobotController` to Delegate to `RobotBackend`

**Files to modify**:
- `robotics/robot_controller.py`
- `tests/test_multi_robot_controller.py`

**Implementation Details**:
- `GenericRobotController.__init__()`:
  - Receives an optional `backend: Optional[RobotBackend] = None`.
  - If `backend is None`, constructs a `PyBulletRobotBackend` using resolved `self.client_id`, `self.robot_id`, `self.arm_joint_indices`, and ordered joint names.
  - Retains existing PyBullet URDF metadata discovery during initialization (documented transitional technical debt).
- `GenericRobotController.get_current_joint_positions()` $\to$ calls `self.backend.get_joint_state().positions`.
- `GenericRobotController.get_current_joint_velocities()` $\to$ calls `self.backend.get_joint_state().velocities`.
- `GenericRobotController.set_arm_joint_positions()`:
  - Applies coordinated slew rate limiting ($\Delta q$).
  - Dispatches rate-limited targets via `self.backend.command_joint_positions(active_targets)`.
  - Returns `active_targets`.
- `GenericRobotController.set_arm_joint_velocities()`:
  - Clamps velocities to `[-max_vel, max_vel]`.
  - Dispatches clamped velocities via `self.backend.command_joint_velocities(clamped_velocities)`.
  - Returns `clamped_velocities`.
