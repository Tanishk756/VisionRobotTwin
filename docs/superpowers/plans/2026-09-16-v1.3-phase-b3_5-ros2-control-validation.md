## 1. Plan Overview & Architectural Directives

Phase B3.5 provides the final verification gate before physical robot backend integration (Phase B4) by validating the complete VisionRobotTwin software stack against real ROS2 Humble `ros2_control` controller plugins (`ForwardCommandController`, `JointStateBroadcaster`) and hardware interface plugins on the official `ros2_control_demo_example_3` RRBot.

### Mandatory Rules:
1. **Strict TDD & Integration-First Sequencing:** Each task creates failing tests or harnesses first, verifies expected failure/behavior, implements minimal code, verifies pass, and commits.
2. **Zero Physical Hardware Commanding:** No physical robot connections, no vendor drivers, no IP configurations.
3. **No Mutating Controller Services from VisionRobotTwin:** Tests launch isolated processes with controllers active. Zero calls to `SwitchController` or `LoadController` from the application.
4. **Observed Closed-Loop State Feedback:** Verification requires actual position changes observed via `ROS2JointStateBackend` on `/joint_states`.
5. **No Version Change:** Repository version remains `VisionRobotTwin 1.3.0-dev`.
