## 📌 Overview

**VisionRobotTwin v1.2.0** transforms the platform from a single-robot teleoperation demonstrator into a modular, robot-agnostic digital twin and robotics research framework. Built on Python 3.10+, OpenCV 4.8+, and PyBullet physics, v1.2.0 introduces multi-manipulator abstractions (**Franka Emika Panda** and **KUKA LBR iiwa**), analytic and geometric kinematics (spatial Jacobian, SVD manipulability, singularity metrics), adaptive DLS resolved-rate Cartesian velocity control, null-space redundancy projection, collision checking, bidirectional RRT-Connect motion planning, and a reproducible task-space experiment suite.

## 🌟 Major Highlights

- **Robot-Agnostic Manipulator Architecture**: Strongly typed model registry and capability descriptors supporting multiple 7-DoF manipulators without hardcoding.
- **Franka Emika Panda & KUKA LBR iiwa**: Complete kinematic models with automated URDF joint hierarchy inspection, controllable joint discovery, and end-effector resolution.
- **Generic Forward & Inverse Kinematics**: Damped Least-Squares (DLS) numerical inverse kinematics solver with measured forward kinematics residual telemetry.
- **Geometric Spatial Jacobian ($6 \times n$)**: Analytic mapping from joint velocities to task-space linear and angular twists.
- **Resolved-Rate Cartesian Velocity Control**: Closed-loop task-space velocity execution with adaptive damping and velocity saturation clamping.
- **Adaptive Damped Pseudoinverse**: Continuous damping factor scaling near kinematic singularities based on smallest singular value $\sigma_{\min}$.
- **Null-Space Joint Centering**: Quadratic joint-centering potential projected onto the Jacobian null space for 7-DoF redundancy resolution without end-effector task disturbance.
- **Manipulability & Singularity Telemetry**: Real-time Yoshikawa index $w(\mathbf{q})$, condition number $\kappa(\mathbf{J})$, and singularity warning alerts on the OpenCV HUD.
- **Joint Quintic & Cartesian SE(3) Trajectories**: $C^2$-continuous joint polynomials and Cartesian trajectories with Spherical Linear Interpolation (SLERP) for orientations.
- **Collision Checking & Simulation State Preservation**: Full self-collision, table, and obstacle proximity queries that preserve PyBullet state during candidate evaluation.
- **Bidirectional RRT-Connect Motion Planning**: Goal-biased tree expansion with randomized path shortcutting for collision avoidance around obstacles.
- **MotionManager Integration**: Runtime bridge unifying FSM goals, collision pre-checks, direct vs RRT trajectory generation, and rate-limited actuator dispatch.
- **World-Anchor Extrinsic Calibration**: 6-DoF extrinsic calibration matrix $\mathbf{T}_{\text{robot}\to\text{camera}}$ estimation via fixed ArUco world-anchor reference.
- **Calibration Quality Tooling**: Comprehensive heuristics for image sharpness, marker area, tilt angle, and spatial coverage.
- **Reproducible Task-Space Benchmark Framework**: Standardized 5-trajectory suite (Line, Circle, Figure Eight, Waypoint Box, SE(3) Sweep) and Obstacle Reach test with provenance-tracked simulation results.
- **131 Automated Tests**: 100% test pass rate across Windows Python 3.11 and Python 3.12 CI.

- **`RobotModelSpec`**: Dataclass specifying URDF paths, base placements, joint regex patterns, end-effector links, joint limits, and rest postures.
- **`RobotCapabilities`**: Explicit capability gating (`has_gripper`, `supports_pick_place`, `supports_velocity_control`, `supports_self_collision`).
- **`GenericRobotController`**: Unified actuator controller handling position stepping, velocity limits, joint queries, and telemetry across all registered robots.

## 📐 Control & Kinematics

### 1. Geometric Jacobian & SVD Manipulability
- Spatial Jacobian $\mathbf{J}(\mathbf{q}) \in \mathbb{R}^{6 \times 7}$ computed directly from PyBullet link and joint transforms.
- SVD decomposition yields singular values $\sigma_1 \ge \dots \ge \sigma_6 > 0$:
  - Yoshikawa index: $w(\mathbf{q}) = \prod_{i=1}^6 \sigma_i$
  - Condition number: $\kappa(\mathbf{J}) = \sigma_{\max} / \sigma_{\min}$
  - Singularity threshold: $\sigma_{\min} < 0.05$ triggers adaptive damping and HUD alert.

### 2. Resolved-Rate Cartesian Velocity Control
- DLS pseudoinverse $\mathbf{J}_{\text{dls}} = \mathbf{J}^T (\mathbf{J} \mathbf{J}^T + \lambda^2 \mathbf{I})^{-1}$ with smoothly varying damping parameter $\lambda(\sigma_{\min})$.
- Null-space projection:
  $$\dot{\mathbf{q}} = \mathbf{J}_{\text{dls}} \mathbf{v}_{\text{task}} + (\mathbf{I} - \mathbf{J}_{\text{dls}} \mathbf{J}) \left( -k_{\text{null}} \nabla H(\mathbf{q}) \right)$$
- Joint limit buffers and per-joint velocity clamping ensure stability.

## 🛡️ Motion Planning & Safety

- **Collision Checker**: Queries PyBullet contact points across robot links, workspace table, and registered obstacle bodies. Simulation physics states are cleanly saved and restored during validation.
- **Bidirectional RRT-Connect**: Explores 7-dimensional joint space to find collision-free paths around workspace obstacles.
- **Randomized Path Shortcutting**: Prunes redundant waypoints and smooths planned trajectories.
- **MotionManager**: Coordinates high-level FSM target commands, pre-flight collision checks, direct trajectory execution when clear, and automated fallback to RRT-Connect planning when obstructed.

---

## 📷 Vision Calibration & World Anchoring

- **Intrinsic Calibration**: Monocular camera matrix and distortion coefficients estimation via standard checkerboard patterns with quality heuristics (sharpness, coverage).
- **World-Anchor Extrinsic Calibration**: Closed-form coordinate transformation solver:
  $$\mathbf{T}_{\text{robot}\to\text{camera}} = \mathbf{T}_{\text{robot}\to\text{anchor}} \cdot \mathbf{T}_{\text{camera}\to\text{anchor}}^{-1}$$
- Robust outlier filtering via sample variance rejection and iterative accumulation.

## 📊 Task-Space Experiments

VisionRobotTwin v1.2.0 includes a reproducible research benchmarking suite (`tools/run_taskspace_experiments.py`) evaluating controllers and robots across standardized trajectories.

> [!NOTE]
> Under the v1.2 PyBullet reference configuration:
> - 45 of 60 deterministic tracking trials satisfied the configured completion criteria.
> - Under the v1.2 PyBullet reference configuration, KUKA resolved-rate control satisfied the configured 10 mm completion criterion across all five reference trajectories, while KUKA numerical IK did not (15 KUKA IK trials did not satisfy the 10 mm completion threshold under this configuration due to numerical IK offsets).
> - Both reference obstacle-reach planning runs produced collision-free plans satisfying the explicit 25 mm endpoint criterion.

Detailed quantitative metrics, time series, and 3D trajectory plots are documented in [docs/experiments/v1.2_reference/REPORT.md](../experiments/v1.2_reference/REPORT.md).

## 💻 Installation & Quick Start

### Prerequisites
- Windows 10 / 11
- Python 3.10, 3.11, or 3.12

### Setup
```powershell
git clone https://github.com/Tanishk756/VisionRobotTwin.git
cd VisionRobotTwin
setup.bat
```

### Quick Commands
```powershell
# Inspect available robot models
python main.py --list-robots

# Run Franka Panda with synthetic vision
python main.py --robot panda --synthetic

# Run KUKA LBR iiwa with synthetic vision
python main.py --robot kuka_iiwa --synthetic

# Run Franka Panda with resolved-rate Cartesian control
python main.py --robot panda --controller resolved-rate --synthetic

# Run task-space experiment suite (headless)
python tools/run_taskspace_experiments.py --all --repeats 3 --headless
```

## ⚠️ Known Limitations

1. **PyBullet Numerical IK Offset on KUKA iiwa**: PyBullet's default numerical inverse kinematics exhibits a steady-state ~20.5 mm position offset on the KUKA iiwa kinematic structure under this orientation frame. Under the v1.2 PyBullet reference configuration, KUKA resolved-rate control satisfied the configured 10 mm completion criterion across all five reference trajectories, while KUKA numerical IK did not.
2. **KUKA iiwa Gripper**: The standard KUKA LBR iiwa model has a bare mounting flange and no gripper joints; autonomous pick-and-place is intentionally disabled on this model.
3. **Physical Hardware Scope**: All robotics control and motion planning have been validated in simulation (PyBullet). Physical manipulator hardware execution has not been conducted.
